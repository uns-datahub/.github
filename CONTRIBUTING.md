# Contributing

Thank you for helping improve UNS OpenHub's public projects.

## Before starting

- Open or find an issue for substantial changes so the scope can be agreed
  before implementation.
- Keep changes focused on one repository and one concern.
- Never commit credentials, local `config.json` files, `.env` files, customer
  data, or generated runtime state.

## Development workflow

1. Fork the affected repository and create a focused branch.
2. Follow the Node.js, package-manager, and setup requirements in that
   repository's README.
3. Run the repository's documented verification command before submitting.
4. Add or update tests when behavior changes.
5. Open a pull request that explains the problem, the approach, and how the
   change was verified.

Small documentation fixes may be submitted directly as pull requests.

By contributing, you agree that your contribution is licensed under the same
license as the repository.
